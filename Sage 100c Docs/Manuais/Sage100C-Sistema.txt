Instalação da aplicação
O seu computador está preparado para trabalhar em condições mais ou menos hostis: consulte as referências dadas pelo seu fornecedor. De um modo geral, recomendamos que verifique o seguinte:
 A alimentação eléctrica do computador e seus periféricos provêm de uma mesma fonte, com a tensão adequada e estável, dentro dos limites indicados pelo fabricante;
 Não há outros aparelhos electricamente ruidosos (aquecedores, frigoríficos ou máquinas industriais) ligados nessa mesma fonte de alimentação;
 Todas as tomadas de corrente usadas têm linha de terra e esta é de boa qualidade;  Não há fios soltos, susceptíveis de serem acidentalmente desligados;  A temperatura e humidade ambientes são aceitáveis para o trabalho de escritório, não
apresentando variações bruscas;  Não há poeira ou fumo a tornar o ar pesado, criando condições para acidentes com
suportes magnéticos. Verifique ainda se existem directivas especiais sobre:
 A ordem recomendada para ligar os vários componentes do sistema informático;  As precauções a tomar para garantir a segurança dos suportes magnéticos (retirar os
mesmos, antes de desligar o sistema);  Programas que devam ser executados ao ligar o sistema, antes de arrancar com esta
aplicação;  Programas que devam ser executados ao terminar a sessão de trabalho, antes de
desligar o sistema;  A ordem recomendada para desligar os vários componentes do sistema informático. O desrespeito das recomendações do fabricante, pode provocar danos materiais ou a degradação da estrutura lógica da informação, implicando prejuízos que podem não ser cobertos por qualquer garantia.
Cuidados prévios
Ao adquirir este produto ficou a dispor dos utensílios suficientes para começar a utilizá-lo ao serviço da sua empresa. Para tal, bastará instalar a aplicação no seu computador e proceder ao registo do licenciamento dos módulos, nas condições que lhe foram atribuídas.
Recomendamos vivamente que tenha a precaução de ler cuidadosamente os manuais distribuídos com a aplicação e de se treinar na utilização do produto, antes de começar a usá-lo para trabalho real.
Requisitos de instalação
As aplicações Sage 100C incorporam a mais recente tecnologia de desenvolvimento de software. Antes de instalar, certifique-se que vai utilizar um sistema correctamente configurado e equipado com os requisitos mínimos de operação.
 Sistema operativo Microsoft Windows 7, Windows 8.1 e Windows 10  Mínimo recomendado de 512 MB;  Drive de DVD-ROM;
7

 Internet Explorer mínimo versão 6. A instalação no sistema operativo Microsoft Windows Vista requer a desativação prévia do Controlo de Acessos de Utilizador ("User Account Control", "UAC").
Instalação
A instalação da aplicação que adquiriu é feita através de um programa criado para esse efeito, que se encontra no DVD-ROM do produto.
A aplicação é distribuída num único pacote de instalação, opcionalmente completado por um conjunto de pacotes de instalação de pré-requisitos. O pacote de instalação da aplicação Sage 100C permite, à escolha do utilizador, a instalação separada dos dois componentes da aplicação, servidor e posto, bem como a instalação de ambos os componentes numa mesma máquina (monoposto). Cada instalação da aplicação implica necessariamente a instalação de um único servidor ou monoposto, e de zero ou mais postos.
A instalação da Saeg 100C efectua, na primeira ocasião em que é executada, e se necessário, a instalação automática dos pré-requisitos de que necessita para o correcto funcionamento dos produtos. Estes pré-requisitos são distribuídos juntamente com o pacote de instalação, numa pasta separada (ISSetupPrerequisites), e incluem os seguintes componentes:
 Sistema Sage, um pacote de instalação contendo um conjunto de componentes Microsoft, e de terceiras partes, necessários ao funcionamento da aplicação.
 Microsoft SQL Server 2008 R2 Express RTM (instalação opcional).  Microsoft SQL Server 2005 Backward Compatibility Pack. É ainda executado como pré-requisito um utilitário de diagnóstico (Diagnóstico de Sistema), que verifica se o sistema é compatível com a instalação do produto, entre outras coisas, verificando se existe instalada na máquina uma versão anterior incompatível com a versão a instalar.
O SQL Server Express 2008 é instalado apenas se o utilizador assim o desejar. Destinando-se nesse caso a ser utilizado pelo componente servidor ou monoposto (ver secção seguinte).
Os restantes componentes incluídos nos pré-requisitos são sempre instalados.
A instalação dos pré-requisitos do Microsoft SQL Server é efectuada com recurso aos conjuntos de instalação fornecidos pela Microsoft. Por isso, estes poderão da mesma forma ser instalados separadamente, antes de instalar a aplicação, recorrendo por exemplo aos conjuntos disponíveis no site da Microsoft.
Pode instalar mais do que um produto da Sage Portugal no mesmo disco.
Se tiver instalada uma versão anterior da aplicação, terá de removê-la antes de instalar a nova versão, instalando depois esta para a mesma localização. A identificação dessa necessidade é feita ao instalar o produto, ao correr o Diagnóstico de Sistema
A instalação é efectuada de forma quase automática, e inicia-se pela verificação dos prérequisitos necessários ao produto. Se um ou mais dos pré-requisitos não se encontrar ainda
8

instalado, é apresentado um ecrã informativo onde se indicam quais os que o irão ser, após confirmação.
Só após a instalação de todos os pré-requisitos obrigatórios é que é lançada a instalação da 100C propriamente dita.
Após o ecrã de boas-vindas, visualizado assim que a instalação se inicia, é apresentado o ecrã de consulta e aceitação dos termos da licença de utilização do produto. E o ecrã de esclarecimentos sobre a Portaria nº 363/2010.
Logo após a aceitação do contrato de licença, indicando assim que pretende proceder à instalação, é pedido ao utilizador que seleccione as aplicações e componentes aplicativos que pretende instalar.
É ainda neste mesmo ecrã que se poderá indicar a directoria onde serão instalados os ficheiros e executáveis de cada um dos componentes seleccionados. Poderá aceitar as localizações sugeridas, ou poderá seleccionar qualquer outra à escolha.
 Pode definir a directoria de destino para a aplicação, diferente daquela que é sugerida por defeito (botão "Alterar"). Por defeito, e caso se trate duma instalação nova, é sugerida a directoria "C:\Sage Data\Main" para o servidor de dados e "C:\Program Files\Sage\Applications" (ou "C:\Programas\Sage\Applications", nos sistemas em português) para o posto.
 O pré-requisito de Diagnóstico de Sistema encarregar-se-á de, automaticamente, sugerir esta localização como a localização de instalação por defeito.
A selecção ou remoção de componentes efectua-se pressionando o componente pretendido, e seleccionando a opção desejada do menu de opções indicado.
É ainda neste mesmo ecrã que se efectua a selecção do tipo de instalação pretendida: Servidor, Posto ou Monoposto.
A instalação do monoposto equivale à instalação do servidor e do posto na mesma máquina. Para a instalação dum servidor, deverá ser removido da selecção o componente "Posto", e todos os seus subcomponentes. Para a instalação dum posto, deverá, pelo contrário, ser removido da selecção o componente "Servidor de dados", ou "Servidores".
 A instalação da aplicação deverá ser iniciada pela instalação do servidor (ou monoposto), já que este componente é encarregue de criar a directoria onde ficam guardados os dados sensíveis da aplicação, e de nela criar os ficheiros essenciais. Durante a instalação dos postos será depois necessário indicar a localização da directoria, pelo que já deverá existir e estar partilhada nessa ocasião.
 A instalação do WebService Sage DGITA pode ser seleccionada de forma independente do servidor de dados, e mesmo do posto. É possível, por isso, a instalação deste serviço com o servidor, com o posto, com o monoposto e isoladamente de qualquer componente.
Instalação Monoposto
9

A instalação monoposto, como foi dito, equivale à instalação do servidor e do posto na mesma máquina. Ao escolher este tipo de instalação os passos a efectuar serão os mesmos duma instalação servidor (descritos na secção seguinte). Leia as secções seguintes para uma descrição pormenorizada desta instalação.
Instalação do servidor
Normalmente, mas não necessariamente, o servidor é instalado numa máquina separada, dedicada exclusivamente a essa finalidade, enquanto que o posto é instalado nas restantes máquinas ligadas entre si e à primeira através de uma rede. Ambos os componentes podem, como já se referiu, ser instalados numa mesma máquina (instalação monoposto; ver a secção anterior). Na instalação do servidor, a directoria de instalação associada ao componente "Servidor de dados", seleccionada no ecrã referido na secção anterior, será a localização centralizada de todos os ficheiros sensíveis da aplicação.
 Esta directoria terá obrigatoriamente que ser partilhada na rede, caso sejam instalados outros postos, e terão ainda que ser dadas permissões totais aos postos, pois todos eles terão que aceder aos ficheiros nela contidos, e nela eliminar e criar outros que venham a ser necessários.
 Deverá ser esta localização a que depois será indicada como localização dos ficheiros comuns aquando da instalação dos postos.
 No caso de não existir um computador com sistema operativo servidor, a versão servidor deverá ser sempre instalada no sistema operativo mais recente.
 Por exemplo: Numa rede na qual coexistem os sistemas operativos Windows 8 e Windows 7, o servidor deverá ser instalado no computador que contém o Windows 8.
 Os sistemas operativos deverão estar atualizados com o último Service Pack disponível. A instalação deve ser efectuada como Administrador de sistema.
 Em Windows 2003 Server, não basta indicar que o grupo pré-definido Everyone tem permissão total, pois a propriedade Modify definida no Security Tab, por defeito está desmarcada, resultando por isso que os utilizadores poderão criar ficheiros, mas não têm direitos para alterá-los. Por estes motivos sugere-se:  Permitir o acesso "Full Control" aos utilizadores ou ao grupo a que os mesmos pertencem.  Sugere-se a não utilização do grupo "Everyone".  É necessário atribuir o direito de "Modify" (na área de "Security") ao grupo ou aos utilizadores.  Inserir o "Local System Account" no mesmo grupo a que pertencem os utilizadores que vão utilizar as Bases de Dados
As bases de dados deverão ser colocadas no mesmo PC de instalação do servidor. A integração de bases de dados em PC’s remotos não é suportada.
A directoria de ficheiros comuns só pode ser alterada via remoção e nova instalação do servidor (ou monoposto).
Ao escolher a instalação do servidor de dados, é de seguida visualizado o ecrã para indicação e autenticação do servidor SQL a utilizar para a criação das bases de dados. Deverá então indicar o
10

nome do servidor (bem como da respetiva instância se não for a instância por defeito, no formato <servidor>\<instância>), e o login e password de uma conta de administrador - já existente - para acesso a esse servidor.
Se na máquina onde a instalação está a decorrer, tiver sido instalado com os pré-requisitos o servidor SQL (o Microsoft SQL Server Express 2008), os dados de identificação e autenticação virão já devidamente preenchidos. Este criará uma nova instância de nome Sage, e a conta "sa" com senha "sage2008+".
A conta a indicar não poderá ser uma conta de autenticação pelo Windows. Terá obrigatoriamente de se tratar de uma conta validada pelo SQL Server, já que todos os postos a utilizarão como conta única de acesso às bases de dados. A conta deverá estar associada no servidor ao administrador do sistema (sysadmin), pois a aplicação utiliza-a para criar e remover bases de dados, entre outras tarefas de administração.
Configuração automática do servidor
No final da instalação, uma mensagem avisa o utilizador de que se irá proceder à configuração automática do servidor. Durante esta fase de configuração, é aberta uma janela de comando, que permanecerá minimizada, sendo efectuadas as seguintes operações:
 Criação das bases de dados de demonstração;  Criação dos dados básicos de registo da aplicação. O serviço do SQL deverá encontrar-se sempre em funcionamento.
Quando esta operação tiver terminado, surge a indicação que a instalação do servidor foi concluída.
Instalação dos clientes (postos)
Se tomou em atenção todas as considerações atrás expostas, está agora em condições de executar os procedimentos para a instalação dos postos da aplicação. Como foi referido, os postos são normalmente, mas não necessariamente, instalados em máquinas separadas do servidor. De seguida, e se se tratar dum posto separado do servidor (ou seja, se não se tratar duma instalação monoposto) é pedido que seleccione a directoria dos ficheiros comuns. No caso da instalação monoposto este passo não é necessário, pois a directoria dos ficheiros comuns é a mesma dos restantes ficheiros
 Esta é a localização centralizada de todos os ficheiros sensíveis da aplicação, incluindo os dados de registo, os scripts em Transact-SQL™ e ficheiros de log e de controlo, entre outros.
 Esta tem que ser a mesma localização que anteriormente foi a indicada como localização do servidor de dados. Não esquecer que esta directoria terá ser partilhada no servidor.
Indicação do servidor SQL Server®
Este passo só é necessário quando já existe uma instalação do SQL Server® 2000 na máquina onde está a ser instalado o servidor da aplicação.
11

Neste caso, a aplicação não instalará uma nova instância, mas utilizará a instância já instalada para a criação das bases de dados. Para que isso possa ser feito, deve ser indicado o nome do servidor (bem como da respectiva instância se não for a instância por defeito, no formato <servidor>/<instância>), e o login e password de uma conta de administrador já existente, ou a ser criada, para acesso a esse servidor.
A conta a indicar não pode ser uma conta de autenticação pelo Windows®. Terá obrigatoriamente de se tratar de uma conta validada pelo SQL Server®, já que todos os postos a utilizarão como conta única de acesso às bases de dados. A conta deve estar associada no servidor ao administrador do sistema (sysadmin), pois a aplicação utiliza-a para criar e remover bases de dados, entre outras tarefas de administração.
Configuração do Servidor
Configuração automática do servidor
No final da instalação, uma mensagem avisa o utilizador de que se irá proceder à configuração automática do servidor. Durante esta fase de configuração, é aberta uma janela de comando, que permanecerá minimizada, sendo efectuadas as seguintes operações:
 Criação das bases de dados de demonstração;  Criação dos dados básicos de registo da aplicação. O serviço do SQL deverá encontrar-se sempre em funcionamento.
Quando esta operação tiver terminado, surge a indicação que a instalação do servidor foi concluída.
Configuração adicional do servidor
Após a instalação, e caso seja necessário, o administrador do SQL Server deverá proceder à configuração dos serviços de modo a que a aplicação funcione sem problemas. Como passo inicial, é necessário que o serviço SQL Server esteja a correr. Para instalações do SQL 2008 é também necessário que esteja a correr o serviço do SQL Browser, para que outros postos na rede visualizem correctamente o servidor. Estes dois serviços são iniciados automaticamente pela instalação do pré-requisito.
As restantes configurações só serão normalmente necessárias quando já exista uma instalação do SQL Server/MSDE anterior à instalação do produto. No entanto, aconselha-se em todos os casos a verificação dos pontos enumerados de seguida, já que da sua observância dependerá a eficaz comunicação entre a aplicação e o servidor, e o bom funcionamento daquela.
Configurações locais
As configurações locais a ter em atenção são principalmente:  A collation a usar por defeito nos campos de tipo texto; uma collation define um conjunto de caracteres a usar e as regras para os classificar e ordenar, bem como outras definições locais específicas; nas instalações novas, a collation usada por defeito é
12

sempre a "Latin1_General_CI_AS"; nas instalações de SQL Server® já existentes, a collation actual poderá ser consultada no Enterprise Manager, nas propriedades do servidor;  Para o funcionamento correcto da aplicação, é absolutamente necessário que o servidor esteja configurado com uma collation compatível com a utilização dos caracteres acentuados e outros caracteres portugueses. No caso do servidor instalado pela própria aplicação, é utilizada a collation "Latin1_General_CI_AS", sendo esta a aconselhada.  Se for preciso alterar a collation por defeito, isso poderá fazer-se ou apenas para as bases de dados da aplicação – executando sobre cada uma delas o comando "ALTER DATABASE <nome da base> COLLATE Latin1_General_CI_AS" – ou, idealmente, alterando a collation do servidor, que implicará a alteração em todas as actuais e futuras bases de dados; esta última alteração terá que ser feita como todos os serviços de SQL Server® desligados, executando na linha de comando a chamada ao utilitário "Rebuildm.exe" para reconstrução da base de dados master;  O formato de inserção de datas; este terá obrigatoriamente que ser da forma <mês><dia>-<ano>, caso contrário as datas gravadas na base de dados ficarão - excepto nos casos em que não haja lugar a dúvidas, como quando o dia é superior a 12, com o dia e o mês trocados;  O formato de inserção de datas (independentemente de qual seja o formato de visualização de datas) é determinado em conjunto pela collation e pela linguagem por defeito associadas ao servidor. No caso do servidor instalado pela própria aplicação, é utilizada a collation "Latin1_General_CI_AS" e a linguagem "English (United States)", que em conjunto definem o formato adequado para inserção de datas.  A alteração do formato de inserção de datas, quando já exista uma instalação do SQL Server®, deverá ser feita antes da instalação do produto, executando por exemplo o comando “SET DATEFORMAT “mdy””, ou alterando a collation e a linguagem por defeito associadas ao servidor.
Outras Configurações
Para que o servidor de SQL Server e os postos comuniquem correctamente um com os outros, é necessário que as Net-Libraries utilizadas para o envio e recepção da informação sejam as adequadas ao protocolo utilizado, e sejam as mesmas no servidor e nos postos.
A selecção das Net-Libraries utilizadas, do lado do servidor, é feita utilizando a Server Network Utility do SQL Server/MSDE 2000. Esta poderá ser executada do menu de programas, caso se trate de uma instalação SQL Server, ou directamente da linha de comando executando o “srvnetcn.exe”.
Em adição às configurações do servidor acima indicadas, é necessário configurar a rede de modo a que a informação que vai ser partilhada entre servidor e postos esteja acessível a estes. Isso significa que terá que ser partilhada pela rede a directoria dos ficheiros comuns indicada aquando da instalação do produto.
Protocolo de comunicação entre servidor e clientes
Como já foi referido, para que o servidor de SQL Server/MSDE e os postos comuniquem correctamente um com os outros, é necessário que as Net-Libraries utilizadas para o envio e
13

recepção da informação sejam as adequadas ao protocolo utilizado, e sejam as mesmas no servidor e nos postos.
A selecção das Net-Libraries utilizadas do lado do posto, é feita utilizando a Client Network Utility do SQL Server/MSDE. Esta poderá ser executada directamente da linha de comando executando o "cliconfg.exe".

Manutenção e acesso a tabelas
Esta tarefa é geralmente desencadeada através da opção Ficheiros, mas também através da movimentação (invocando a barra de botões ou respetiva tecla de função). Permite efectuar a criação, alteração ou anulação de dados, nos ficheiros mestres e tabelas.
A selecção de ficheiros (exemplo: Clientes, fornecedores, artigos, plano de contas, funcionários, etc.) entra, de imediato, com a máscara em modo de criação (introdução, correcção ou anulação). A abertura de tabelas de apoio (exemplo: Zonas, vendedores, etc.) entra sempre em modo de lista.
Na lista que lhe é disponibilizada pode:  Deslocar-se na lista com as teclas de movimentação ou o rato;  Com <Enter> ou duplo clique no rato aceder à janela de manutenção para edição do registo onde está posicionado o cursor;  Criar registos com <Ctrl><N>.
Se seleccionar um registo e usar <Enter> (ou função correspondente) na janela da lista, surge de imediato a janela de manutenção dos registos, posicionando-se o cursor no primeiro campo. Ao introduzir informação neste campo, a aplicação verifica se já existe um registo com essa "chave".
 Se existir é carregada toda a informação respeitante a esse registo;  Se a "chave" que introduziu não corresponde a um registo existente, o sistema entra
automaticamente em modo de criação de registos, ou seja, a ficha apresenta todos os campos de dados a branco. Neste ponto dispõe de cinco alternativas:  Manter o registo inalterado - Seleccionar o botão "Cancelar" ou usar o <Esc>;  Apagar o registo - Seleccionar o botão "Anular" e confirmar anulação na janela de mensagem que surge de seguida;  Modificar o registo - Posicionar-se no campo pretendido e substituir o conteúdo, quando tudo estiver correcto seleccionar o botão "Confirmar";  Gravar o registo - Seleccionar o botão "Confirmar" e o registo será gravado com os dados presentes na ficha;  Duplicar o registo - Alterar apenas o código e validar com o bottão "Confirmar".

Rato
A utilização de dispositivos apontadores (exemplo: Rato, track ball, etc.) é comum a todas as aplicações para o sistema operativo Microsoft Windows®, proporcionando ao utilizador a selecção das opções a executar, de forma mais rápida, reduzindo ao mínimo a necessidade de digitação no teclado. Acesso às listas
Campo em edição
Como foi dito atrás uma lista está normalmente associada ao campo em edição, ou seja, o campo onde está posicionado o cursor.
O campo em edição identifica-se pela cor de fundo diferente dos restantes (esta cor é configurável pelo utilizador) e pela presença do cursor.
As listas estão disponíveis em todas as janelas da aplicação e em todos os campos, desde que estejam associados a uma qualquer das tabelas da aplicação.
Exemplo: Na tabela de Clientes, estando posicionado no campo morada, a lista apresentada será a lista de Clientes existentes. No entanto, caso o campo em edição seja, por exemplo, o campo zona, a lista já não será a lista de Clientes mas sim a lista de zonas geográficas.
O acesso às listas pode ser feito pelo ícone disponibilizada na barra de comandos (descrita acima), ou utilizando o conjunto de teclas <Ctrl><L>.

Se seleccionar a exportação para formato Microsoft Word© ou RTF (Rich Text Format), dispõe ainda de duas opções adicionais:
 Preservar as fontes originais

 Usar tabelas para conter a informação

Enviar por e-mail O ficheiro destino da exportação pode ser enviado por correio electrónico, se existir um servidor de correio correctamente configurado, o processo encarrega-se de proceder à criação e envio de uma mensagem. Os dados que lhe são solicitados dizem respeito ao destinatário da mensagem. Após concluir a operação, é apresentada a mensagem a enviar, que deve alterar da forma que achar conveniente.
Foi imposta a limitação de, no máximo, três processos de envio em simultâneo por e-mail dos ficheiros gerados. É avisado caso tente marcar para envio quando o número máximo já foi atingido. De forma semelhante, se sair da aplicação enquanto se encontrar a decorrer um envio, é alertado desse facto e pode, se assim o desejar, terminar esse envio posteriormente.
Para assegurar que um processo, uma vez iniciado, não fique esquecido e para possibilitar o seu cancelamento depois de iniciado, será afixada pela aplicação, a cada cerca de 5 minutos, uma mensagem à qual pode responder continuando ou terminando o processo.
No caso da exportação de documentos para os formatos Texto e Excel, existe ainda a possibilidade de ajustar as dimensões das linhas e colunas do documento, de modo a otimizar o resultado da exportação. Esse ajuste é feito manipulando os dois cursores situados na pasta Configuração. De um modo geral, não será necessário proceder a estes ajustes, porque a exportação tenta sempre otimizar os resultados para o documento a exportar. No entanto, caso o documento contenha linhas muito próximas umas das outras (ou, pelo contrário, muito afastadas umas das outras), ou campos horizontalmente colocados muito próximos uns dos outros (ou, uma vez mais, muito afastados), pode acontecer que o ficheiro gerado ignore algumas das linhas ou campos, ou esteja a colocar linhas ou colunas vazias entre as restantes. Nestes casos é conveniente proceder ao ajuste descrito. Este ajuste é feito com base nas seguintes indicações:
 Se o ficheiro exportado estiver a ignorar algumas linhas, é porque estas linhas no documento original estão demasiado próximas umas das outras: neste caso,
26

experimentar reduzir a altura da linha (resolução vertical), movendo o cursor respetivo para a esquerda;  Pelo contrário, se o ficheiro exportado estiver a colocar linhas em branco entre as restantes, é porque estas linhas no documento original estão demasiado afastadas umas das outras: neste caso, experimentar aumentar a altura da linha (resolução vertical), movendo o cursor respetivo para a direita;  Se o ficheiro exportado estiver a ignorar alguns campos (ou a juntá-los horizontalmente uns com os outros), é porque estes campos no documento original estão demasiado próximos uns dos outros, horizontalmente: neste caso, experimentar reduzir a largura da coluna (resolução horizontal), movendo o cursor respetivo para a esquerda;  Pelo contrário, se o ficheiro exportado estiver a colocar colunas vazias entre as restantes, é porque os campos no documento original estão demasiado afastados uns dos outros, horizontalmente: neste caso, experimentar aumentar a largura da coluna (resolução horizontal), movendo o cursor respetivo para a direita. Em muitas situações, dada a configuração particular do documento em causa, pode ser necessária uma solução de compromisso entre as diversas possibilidades.
Gravar as alterações efectuadas A lista é totalmente configurável pelo que deve usar o icon Gravar para confirmar as alterações efectuadas na lista, de forma a serem tomadas em consideração na próxima vez que aceder a esta. É possível gravar todas as parametrizações da lista, com excepção dos critérios de pesquisa rápida, por se tratarem de critérios de carácter temporário. Se desejar configurar um conjunto de critérios e preservar essa configuração, deve recorrer aos critérios detalhados.
Para evitar a saída acidental de uma lista que tenha sofrido alterações de configuração, o utilizador é avisado desse facto, podendo guardar as alterações se assim o desejar.

 Da direita para a esquerda, a coluna a recolocar será posta à esquerda da coluna onde se deixou de premir o botão esquerdo do rato.

Estes últimos são indicados visualmente na lista de campos através do símbolo de função. Todos os campos a partir dos quais se pode aceder à tabela que está associada aos mesmos, para se colocar informação associada são representados com o sinal "mais". Exemplo: Associada à tabela de Clientes temos a tabela de Códigos postais (associação pelo campo Código postal) e também a tabela de Balcões (associação pela chave constituída pelos campos Banco e Balcão).

Remover campo
Esta operação não se encontra disponível nas listas por SQL. A selecção desta opção, ou o uso das teclas <Ctrl><P> permite apagar colunas da lista. Para tal, basta marcar previamente a coluna a remover e executar esta opção.
A coluna deixa de aparecer na lista, mas pode, obviamente, ser inserida novamente.
Esta operação é constituída pelos seguintes passos:  Clicar com o rato em qualquer área da coluna pretendida;  Ao clicar na coluna a célula ficará com o fundo a cor diferente, o que significa que foi efectuada a selecção da mesma;  De seguida executar a opção de anulação.
Certifique-se, antes de executar, que a coluna marcada é a que realmente pretende remover.
Filtros
A utilização de filtros permite definir condições para a extracção de registos na lista. A configuração desses filtros baseia-se na indicação explícita de valores ou mesmo de intervalos, a considerar para um ou mais campos.
Desta forma, os registos cujos campos não obedeçam ao intervalo definido ou não contenham o valor previamente indicado, não serão mostrados na lista.
Não é necessário que um dado campo esteja presente na lista para que se possam definir critérios de filtros sobre ele.
Criação de Filtros
Clicando no botão "Filtros", que é mostrado na barra de ferramentas da janela da listagem, poderá seleccionar os filtros a aplicar à listagem, estes filtros podem estar previamente configurados, ou podem ser configurados a partir da janela que será aberta neste momento. Responsável de sistema
O conceito de responsável do sistema, advém da necessidade de certos aspectos do trabalho com a aplicação, necessitarem de alguns cuidados especiais e de acesso reservado. Os cuidados especiais, referem-se à configuração dos dados das empresas, à definição dos utilizadores e respectivos níveis de acesso, assim como a todo o procedimento de licenciamento dos módulos.
Estas operações, como é óbvio, têm que ficar reservadas a algumas pessoas na empresa, normalmente ao administrador do sistema, a fim de evitar que qualquer elemento não autorizado, possa proceder a alterações de fundo, na estrutura da aplicação.
Apesar de não ser obrigatória, é veementemente aconselhada a existência de um código de acesso específico, que garanta a limitação do acesso a estas funções, que iremos designar por senha do responsável de sistema. Mais abaixo iremos explicar como deve configurar esta senha.
Nas instalações licenciadas, o acesso a estas funções, ficam limitadas aos conhecedores dessa senha. As instalações em versão de demonstração, não contêm qualquer limite de acesso a estas funções. Será necessário aceder às funções de responsável de sistema quando pretender:
 Criar novos utilizadores ou alterar o perfil daqueles que já existem;  Criar uma nova empresa;  Aceder aos parâmetros (dados) da empresa;  Proceder ao licenciamento de módulos;  Compactar a base de dados, etc.

Para qualquer tarefa poder executar, a responsável de sistema tem que estar a correr no sistema operativo, excepto quando o tipo de agendamento é Executar.
Em todos os tipos de agendamento a decisão de executar, ou não, a tarefa no momento em que é sugerida pela aplicação fica a cargo do utilizador, no entanto é possível definir um intervalo de tempo a partir do qual a execução da tarefa passa a ser obrigatória. Esse intervalo é definido na pasta Agendar, no campo "Alertar após x dias". Por defeito, este campo é preenchido com 365 dias, que é o número de dias máximo em que é possível estar sem executar essa tarefa, mas o responsável de sistema poderá definir o número de dias que pretender, desde que inferior a 365.

Utilização do Agendamento de tarefas com o Task Scheduler
As tarefas que foram criadas na opção podem ser chamadas a executar directamente a partir do Task Scheduler do sistema operativo, sem que a Responsável de Sistema esteja a correr. Para tal no Task Scheduler deve usar:
Sage.BSIS.exe /%switches%
%Switches% podem ser os seguintes: /Tasks – Verifica nas tarefas agendadas se existe alguma que deva ser executada. /Task=BACKUP– Manda executar a(s) tarefa(s) com nome BACKUP1. Normalmente estas tarefas têm o tipo de agendamento externo, ou seja a ordem de execução vem de comandos externos como o scheduler do windows.
Exemplos:
Sage.BSIS.exe /tasks – Inicia a RS verifica e executa tarefas pendentes, sai de seguida.
Sage.BSIS.exe /task=backup1 /task=backup2 – Inicia a RS e executa tarefa(s) com nome = “backup1” e “backup2” , sai de seguida.
O Task Scheduler, também se pode chamar Windows Scheduler ou Tarefas Agendadas, pode localizar-se em Acessórios – Ferramentas de Sistema ou também no Painel de Controlo\Ferramentas Administrativas dependendo do sistema operativo que usar.

A área de trabalho
O ambiente de trabalho (desktop, working area) serve de contentor para um conjunto de conteúdos que podem grosseiramente ser classificados em:
1. Atalhos para funcionalidades das aplicações, mais ou menos agrupados ou classificados de forma a facilitar o acesso e a conceptualizar certas acções e processos: é o caso, por exemplo, dos diagramas de processo e das pré-visualizações dos mapas.
2. Indicadores de negócio e de gestão, sobre a empresa em que se está a trabalhar: é o caso dos gráficos e listas de dados de, por exemplo, vendas.
3. Informação de controlo de processo, como alertas e avisos. 4. Outra informação de negócio, como dados da empresa, listas de entidades... 5. Informação não directamente relativa ao negócio, como notícias. Na área de trabalho, este conjunto de funcionalidades encontra-se agrupado em painéis, dispostos em matriz sobre a área útil da área de trabalho. Além do conjunto de painéis, pertencem ainda à área de trabalho a informação sobre a licença e o contrato adquiridos, os atalhos para os comandos específicos da área e o logótipo Sage. Estes encontram-se agrupados na zona superior da área de trabalho, a que podemos chamar a área não útil.
A personalização da área de trabalho permite ao administrador da instalação:  Remover painéis pré-configurados que vem de base com o produto;  Acrescentar novos painéis a qualquer área pré-configurada, venha ou não de base com o produto;  Modificar a ordem de apresentação dos painéis dentro da área de trabalho;
60

 Alterar as propriedades (título, parâmetros...) dos painéis anteriormente configurados, venham ou não de base com o produto;
 Atribuir ou retirar a cada utilizador ou grupo da instalação permissão para visualizar painéis;
 Repor a configuração base (original) de uma qualquer área anteriormente configurada;  Repor a configuração base (original) de todas as áreas de trabalho. O conteúdo da área útil da área de trabalho (os painéis) pode ser definido de forma diferente para cada pasta da barra de navegação lateral, a que se chama tema. Em alternativa, pode definir-se uma área de trabalho por omissão, isto é, uma que será utilizada em qualquer tema para o qual não esteja definida uma área própria. A definição do conteúdo das áreas de trabalho, e da sua associação aos temas da barra de navegação lateral, vem de base com os produtos, mas, como veremos mais à frente, pode ser totalmente reconfigurada pelo administrador da instalação.
A gestão do espaço ocupado por cada painel e do posicionamento duns painéis relativamente aos outros é feita de forma automática, e do modo seguinte: a área útil é dividida numa grelha arbitrária de 2 “colunas” por 8 “linhas”; cada “célula” desta grelha pode contem um painel, cabendo na área, por isso, um máximo de 16 painéis. A distribuição dos painéis faz-se sequencialmente, a partir do primeiro, com base nas seguintes propriedades de cada painel:
 Largura, em “células” da grelha; um painel pode ocupar 1 ou ambas as colunas;  Altura, em “células” da grelha: um painel pode ocupar de 1 a 8 linhas;  Se o painel pode ou não expandir-se na horizontal (alargar-se) de forma a ocupar
colunas adjacentes: em caso afirmativo, se o painel for colocado na primeira coluna e a segunda estiver vaga, ele alargar-se-á para ocupar ambas as colunas;  Se o painel pode ou não expandir-se na vertical (crescer) de forma a ocupar linhas adjacentes: em caso afirmativo, se o painel for colocado numa linha e as linhas seguintes estiverem vagas, ele crescerá para ocupar essas linhas; note-se que o crescimento de um painel nunca poderá ultrapassar o número de linhas visíveis no ecrã, isto é, um painel não pode crescer além da área visível no ecrã, mesmo que hajam linhas vazias mais abaixo Por exemplo, na área de trabalho da figura seguinte inseriu-se um painel de dimensões 1 x 1 que não cresce nem se alarga (“Informação da Empresa”) ao lado dum painel 1 x 1 que cresce e se alarga (“Notícias Gestão Empresarial”). Este painel cresceu de forma a ocupar as duas linhas livres situadas abaixo dele, mas não de forma a ocupar as restantes cinco linhas situadas já fora da área visível do ecrã. Note-se que a distribuição dos painéis pela área útil é sempre feita de forma a tentar ocupar todos os espaços livres. Isso quer dizer que um dado painel, mesmo que esteja posicionado abaixo de um outro, poderá eventualmente vir a aparecer acima dele, para ocupar espaços livres nos quais o outro não cabe.

Caraterísticas comuns aos painéis de informação
Todos os painéis de informação (painéis de indicadores, painéis de notícias, ...) têm que obter a informação de alguma forma: das bases de dados, da Web, de processos que os calculam em tempo real... Na maior parte dos casos o custo (o tempo, a disponibilidade) de obtenção desta informação é elevado, e nem sempre suportável pelos utilizadores.
62

Para minorar este custo, e mesmo assim possibilitar ao utilizador comum o benefício de toda esta informação, os painéis que necessitam de obter dados apresentam duas características comuns, e importantes, que se descrevem em seguida:
1. Sempre que um ou mais destes painéis necessita de obter os dados para representar, fá-lo num processo separado, isto é, fá-lo em paralelo (e em simultâneo) com a própria aplicação, sem obrigar a aplicação a ficar à espera que a obtenção dos dados termine. Isso permite que se possa ir iniciando o trabalho na aplicação mesmo antes dos dados estarem disponíveis. Enquanto o painel estiver a carregar os seus dados, aparecerá a cinzento, com a informação “A carregar...”.
2. Além disso, os dados representados em cada painel, uma vez obtidos, são armazenados num local de fácil acesso (no que se chama um cache) de onde é muito mais rápido carregá-los. Assim, das próximas vezes que o painel tiver que obter os seus dados, pode fazê-lo a partir desse local, com um custo muito menor do que o necessário para os obter novamente da base de dados ou da Web.
Assim, por exemplo, da primeira vez que se entrar numa aplicação, os painéis de dados terão necessariamente de ir buscar os seus dados à origem, já que estes ainda não se encontram armazenados em cache. Mas da segunda vez que isso for feito (ou da primeira vez mas num outro posto, como se irá ver mais à frente), esses dados já serão obtidos do cache entretanto criado com os dados originais, sendo por isso o seu carregamento muito mais rápido.
O armazenamento dos dados em cache é vantajoso, além disso, noutros sentidos:  Os caches são armazenados em locais comuns a toda a instalação (pasta partilhada em rede, base de dados da empresa). Por isso estão disponíveis para todos os postos da rede: é suficiente que um deles tenha o trabalho de o actualizar, e todos os outros beneficiarão dessa actualização.  Os caches são partilhados por todos os painéis que representem os mesmos dados. Por isso estão disponíveis para todos os painéis iguais, onde quer que eles estejam inseridos. Se o utilizador optar por inserir um mesmo painel em várias das suas áreas de trabalho, o custo de obtenção dos dados é apenas um único.
Os caches dos produtos são actualmente guardados em ficheiros encriptados, na pasta de rede do servidor de dados.
Os caches têm, contudo, uma desvantagem óbvia: a informação neles contida não está actualizada, tendo sido obtida numa ocasião anterior àquela em que eles estão a ser utilizados. Para ultrapassar esta limitação, existem duas formas de actualização dos dados antigos guardados nos caches:
1. Actualização manual: o utilizador pode, a qualquer altura, forçar a actualização dos dados através do comando “Actualizar”. Pode ainda fazê-lo para um painel individual, accionando o comando de actualizar desse painel (situado no canto superior direito do painel), ou para todos os painéis da área de trabalho (apenas os da área de trabalho em que está, não os das outras), accionado o comando de actualizar da área, situado na zona superior da mesma.
2. Actualização automática por definição do prazo de validade dos dados: se a informação associada a um dado painel tiver sido definida com um prazo de validade, após o termo desse prazo os dados serão automaticamente actualizados, sem intervenção do utilizador.

Condições de extracção de dados
Condição sobre o nível O botão acede à definição de condições para a extracção dos níveis a que se aplica. Podem ser usados na definição de condições sobre os níveis, campos calculados ou funções.
As condições aplicam-se ao nível de uma forma global e não a um campo específico de cada um dos níveis. Se pretender estabelecer condições para um campo em especial deve optar pela selecção de Campos calculados.
Em todos os casos em que existam dois ou mais níveis de extracção de dados é obrigatório seleccionar quais os campos chave que estabelecem a relação entre os níveis (exemplo: Cabeçalhos e linhas).
De notar que a condição estabelece-se sempre no nível de grau inferior referenciando campos dos dois níveis.
Exemplo: Para um documento comercial, foi seleccionada a tabela Documentos GC Cab (cabeçalhos) para o nível 1 e a tabela Documentos GC Lin (linhas) para o nível 2.
Nesta situação deve verificar que neste nível (cabeçalhos) só serão extraídos dados dos documentos comerciais de clientes.
Deverá igualmente estabelecer uma relação entre os cabeçalhos e as linhas com os campos chave de ambas as tabelas (Ano, tipo de documento, série e número de documento).
Veja em Funções mais informações de como construir uma condição ou um campo calculado.

Isolada Indicação da extracção isolada deste nível, ou conjunta deste com outro nível.
